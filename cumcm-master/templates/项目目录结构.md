# 数学建模参赛项目目录结构范式

> 可直接复制套用。命名规范保证「代码 → 论文 → PPT」三处一致。

```
项目根目录/
├── data/                     # 原始数据，命名保持题目附件原名
│   ├── 附件1.xlsx
│   ├── 附件2.xlsx
│   └── ...
├── code/                     # 全部 Python 代码，按「职能」拆分脚本
│   ├── main_solver.py        # ★ 主求解器（唯一出数值结果的脚本）
│   ├── figures_main.py       # 主图表（正文核心图）
│   ├── figures_analysis.py   # 分析图表（FFT/残差/灵敏度等）
│   ├── figures_supplement.py # 补充图表
│   └── config.py             # 全局配置（色板、字体、路径）
├── figures/                  # 所有图表 PNG，编号命名
│   ├── fig0_xxx.png
│   ├── fig1_xxx.png
│   └── ...
├── results/                  # 求解输出的 CSV（可追溯的数值快照）
│   └── final.csv
├── paper/                    # 论文目录
│   ├── cumcmthesis.cls       # 官方模板类文件
│   ├── paper.tex             # ★ 论文源码（唯一编译入口）
│   └── paper.pdf
├── AI工具使用详情.md         # 2025 新规强制提交件
├── PPT提示词.md              # 交给豆包/Kimi 的 PPT 生成提示词
└── 汇报稿.md                 # 答辩材料
```

## 命名规范要点

- **图**：`fig{序号}_{英文内容}.png`，正文编号 0–9 与文件名一一对应（fig0=光路图…fig9=综合对比），保证论文 `\includegraphics` 与磁盘文件可一一核对。
- **代码**：一个脚本一个职责；主求解器不画图，绘图脚本不复算最终结果（复用求解器函数）。
- **数值结果落盘**到 `results/`，论文数值与 CSV 交叉核对。

## 关键原则

**数值结果（`results/` CSV）是「代码 → 论文 → PPT」三者的唯一事实源**——任何数值改动都要从代码重新生成，并回写到论文和 PPT，保证三处一致。
